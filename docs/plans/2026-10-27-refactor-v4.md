# 2026-10-27 Refactor Plan V4

## Objective

Build a new layered one-game MVP while preserving legacy external behavior until explicit cutover.

## MVP

```text
main menu -> traditional battle -> deck selection -> mulligan
-> recommendation-driven play -> one complete game -> settlement -> stop
```

## Architecture

- `domain`: immutable GameSnapshot, CardDefinition, ActionIntent, ActionPlan, pure rules.
- `application`: use cases, ports, PlanBuilder/Validator/Executor, StopToken, ActionGate, plugins.
- `adapters`: HSAng, Power.log, lobby, input, config, cards, journal, artifacts.
- `bootstrap`: only composition root.
- `entrypoints`: `uv run hslegend-onegame`.

## Agent Workflow

- Main Controller owns global state and integration.
- One fresh Implementer and one fresh Reviewer per task.
- Task Book + interface + allowed files are the complete implementer context.
- At most three review/fix rounds.
- One final squash commit per task.
- No direct push to `main` or `develop`.
- Native tests are opt-in.

## Task Sequence

```text
R00 governance
-> R01 uv baseline
-> R02 contracts, golden replay, CI gates
-> R03 domain contracts
-> R04 application ports/runtime
-> R05 plan and execution pipeline
-> R06 data adapters
-> R07 external adapters
-> R08 enter battle
-> R09 mulligan
-> R10 turn loop
-> R11 settlement/stop
-> R12 CLI and fake full game
-> R13 native one game and main cutover
-> R14 static plugin expansion
-> R15 control-plane security
-> R16 legacy migration and cleanup
```

## Verification

Every task must pass task-specific tests, architecture checks, scope checks, and independent review. Completion claims require fresh command evidence.

## Non-Goals

- No big-bang rewrite.
- No Web/overlay/scheduler/concede/watchdog in MVP.
- No dynamic plugin discovery.
- No pip/Conda/system Python.
- No coordinate, delay, threshold, or click-sequence changes.
