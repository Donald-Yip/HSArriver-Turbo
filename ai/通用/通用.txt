通用策略（`ai/通用/通用.py`）——不依赖具体卡组、不写卡牌 ID 的兜底基线
========================================================================

一、什么时候用
--------------
1. 网页「👤 基础配置 → 🤖 策略选择」直接选「通用」：用一套通用打法把任何卡组跑起来。
2. 网页「盒子推荐失效兜底」选「通用」：盒子 AI 推荐读不到/一直不可执行时自动接管，
   盒子恢复后自动切回（这是本策略的主要用途）。

它不是“最强 AI”。它的目标是：**盒子失效时别停摆**，并给用户一个可自己调权重的
基线。具体卡组的连招、关键牌、任务进度，通用策略一律不认识——那些留给
`ai/任务牧`、`ai/动物园术` 等卡组专属策略。


二、评分框架（与 `ai/动物园术` 同形）
--------------------------------------
    RANKS_FROM_SEQUENCE_START = True
    rankState(state, actions)
        = rankStaticState(终局场面) + rankActions(动作序列)

* `rankStaticState`：终局场面分（英雄生命、手牌、双方随从、武器、地标、
  威胁等级、斩杀线）。搜索的“敌方回合模拟”也用它。
* `rankActions`：只补“终局场面相同、但动作顺序有浪费”的溢出伤害惩罚
  （用 3/3 撞 2/1 多打出的 2 点，每点扣 0.5）。不写具体牌的效果分。
* 搜索里每个节点都会把动作序列从起点重放，拿终局场面评分（`doAction`），
  所以“打出一张随从/攻击换血”的结果由终局静态分体现，动作分不需要重复加。


三、静态特征与权重（文件顶部常量，可直接改）
--------------------------------------------
| 特征 | 基线 | 说明 |
| --- | --- | --- |
| 我方英雄有效生命 | `hp<=15` 时每点 1；高于 15 的部分每点 0.2 | 低血才值钱（Jev/MetaStone） |
| 敌方英雄有效生命 | 同函数 × -1.2 | 打死对面比保自己更接近胜利 |
| 我方手牌 | +3/张 | MetaStone/Silverfish |
| 随从固有 | +1 | MetaStone |
| 随从攻击 | +2/点（冻结/休眠/无法攻击按 0） | MetaStone/Silverfish |
| 随从生命 | +2/点 | MetaStone 默认 1、训练 3 的折中 |
| 嘲讽 | 绿 0.7 / 黄 4 / 红 8 | 威胁越高越值钱（MetaStone） |
| 风怒 | +2 | MetaStone |
| 圣盾 | +2 | MetaStone |
| 法强 | +1/点 | MetaStone |
| 潜行 | +1 | MetaStone |
| 突袭/吸血 | +1 | 现代关键词的通用加成 |
| 剧毒 | +3 | Silverfish 毒 +4 的折中 |
| 复生 | +1.5 | 通用 |
| 冻结/休眠 | 攻击按 0，整体 ×0.7 | Silverfish |
| 武器 | 攻 × 耐久（我方正、敌方负） | Silverfish |
| 地标 | 耐久 × 1.5（我方正、敌方负） | 通用 |
| 敌方低血 | 敌方生命 <12 时 +(12-敌血) | Silverfish 低血更多打脸 |
| 敌方斩杀线 | 敌方场面攻击+英雄攻击 >= 我方生命+嘲讽墙 → -50 | Jev |
| 威胁等级 | 红 -40 / 黄 -12 | MetaStone |
| 斩杀/阵亡 | 敌血 <=0 → +10000；我血 <=0 → -10000 | Silverfish/MetaStone |

威胁等级（同时决定嘲讽权重和红/黄惩罚）：

    敌方伤害 = Σ(敌方随从攻击 × (2 if 风怒 else 1)，排除冻结/休眠/无法攻击)
             + max(0, 敌方英雄攻击)
    我方生命 = 英雄当前生命（含护甲）
    剩余     = 我方生命 - 敌方伤害
    红 = 剩余 < 1；黄 = 剩余 < 15；绿 = 其它


四、换牌
--------
* 换掉 `current_cost >= 5` 的牌，至少保留一张（最便宜那张），幸运币不换。
* 参考 MetaStone 的“高费换掉”，但门槛取 5 更保守。
* 想全部保留：把文件顶部 `MULLIGAN_REPLACE_COST` 改大（例如 99）。
* 换牌兜底（盒子换牌 OCR 失效时）也走这套规则；`MulliganFlow` 仍会再按
  可点击位过滤一次，绝不点幸运币/越界位。


五、怎么调
----------
* 所有权重都在 `通用.py` 顶部“评分常量”区，改常量即可，不需要动搜索框架。
* 觉得太保守（不爱出牌）：调低 `OWN_CARD_COUNT` 或调高 `MINION_ATTACK_FACTOR`/
  `MINION_HEALTH_FACTOR`。
* 觉得太激进（老想打脸）：调高 `OWN_CARD_COUNT`、`ENEMY_HERO_VALUE_FACTOR` 或
  `LOW_ENEMY_HP_BONUS` 调低一些。
* 经常被斩杀：把 `THREAT_RED_PENALTY` / `LETHAL_DANGER_PENALTY` 调得更负。
* 溢出伤害惩罚：`OVERKILL_PENALTY`（0 = 关闭动作分）。

七、已知局限
------------
* `doAction` 对未知卡牌效果模拟不完整：通用策略可能低估某些法术/连招。
* 不猜对手手牌、不猜牌库顺序；`AiState` 也没有敌方手牌计数字段。
* 不读 `cards.json` 做卡牌 ID 分支——这是故意保持“通用”。
* 因此：优先用卡组专属策略；通用策略只在盒子失效或没有专属策略时用。
